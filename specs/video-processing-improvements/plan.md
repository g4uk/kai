# Plan: Video Processing Improvements

Implements `specs/video-processing-improvements/spec.md`. Touches `internal/video` (persistence-scored top-N selection, configurable thresholds, download-integrity validation, stage-progress callback), `internal/jobevents` (new `StageChanged` event + `Type` discriminator), `cmd/worker/main.go` (stage-event publishing, categorized/redacted failure summaries, new env vars), and `internal/handler/jobs_stream.go` (SSE event-name discrimination so stage events never corrupt the existing status-toast flow). No DB migration, no `web/` changes, no new HTTP endpoints.

## Risks

1. **The persistence-score heuristic is not guaranteed to always separate fighters from an unusually still fighter or unusually active referee.** Accepted per spec Constraints — this is the locked-in MVP tradeoff (heuristic, not ML), not a bug to chase in this plan.
2. **`Pipeline.Run` and `Processor.Process` both gain new parameters** (`onStage`, and `Processor` additionally threading it through). Every existing fake/test in `internal/video` and `cmd/worker` must be updated to the new signature without changing what they already assert — an intentional signature change, called out here and in the step 7-8/9-10 commit messages so it's never only discoverable via `git diff`, mirroring `specs/video-processing/plan.md` Risks #2's precedent.
3. **SSE `type`-discrimination depends on every event producer setting `type` correctly.** Step 12's fallback (default to `job_status` if `type` is missing/unparseable) prevents a hard failure, but a future event producer that forgets `type` would have its events misrouted as status toasts rather than silently dropped. Documented and tested (step 11's third case), not just assumed.
4. **`MaxParticipants` defaulting to 2 is a deliberate behavior change** from today's "keep every detected region" (spec Constraints already surfaces this explicitly) — step 2's implementer must not treat criterion 10 as optional or accidentally preserve the old "unlimited" default.
5. **The new ffprobe-based integrity check adds one more subprocess invocation per attempt.** Expected to be fast (single-stream metadata check on an already-downloaded file) and not meaningfully affect the `PROCESSING_TIMEOUT` budget, but noted as a minor added latency source, not benchmarked in this plan.
6. **Persistence-score tracking requires per-frame-pair (not just accumulated-total) cell activity**, changing `accumulateCellDiffs`'s memory shape from `rows*cols` to effectively `rows*cols*pairs`-aware bookkeeping. Bounded by the existing 1fps sample rate and 32px-default grid coarseness — not expected to be a real performance concern, but it's a genuine algorithmic change worth a second look in review, not a drop-in refactor.
7. **Distinguishing "download failed" vs "analysis failed" (the two categories without an existing sentinel)** requires the implementer to add a small stage-tagging mechanism in `internal/video` (step 10) — if this turns out messier than expected (e.g., conflicts with how `runAttempt` already wraps errors with `fmt.Errorf("video pipeline: download: %w", ...)`-style prefixes), the implementer may propose reusing those existing string prefixes via `strings.Contains` as a fallback; that would be a plan deviation and must be surfaced explicitly in the step 9/10 commit message and as a spec amendment, not silently substituted (per CLAUDE.md's deviation rule) — sentinel/typed-error is the preferred approach and should be attempted first.

- `internal/otp/`, `internal/session/`, `internal/user/` — authentication is untouched.
- `internal/db/migrations/` — no new migration; schema reuse only.
- `job.validTransitions` and the `status` column's valid values in `internal/job/job.go` — unchanged (`pending→processing`, `processing→done/failed`); stage events are ephemeral pub/sub, never persisted.
- `internal/job/job.go`'s `SaveResults`/`SaveSummary` signatures — unchanged; they already accept whatever `[]video.ParticipantResult`/`string` they're given, so top-N filtering and redacted failure text require zero changes here.
- Any ML/CV dependency (gocv, OpenCV bindings, MediaPipe, PyTorch, ONNX runtime) — pure Go + `yt-dlp`/`ffmpeg`/`ffprobe` subprocess only, per spec Non-scope.
- `Dockerfile` — no new binaries or system packages; `docker-compose.yml`'s `worker` service only gains 4 new optional env var entries. `api`, `web`, `mysql`, `redis` services untouched.
- `POST /jobs`, `GET /jobs`, `GET /jobs/:id` request/response shapes in `internal/handler/jobs.go` — unchanged; only `job_summaries.summary`'s *text content* changes, not the field or its type.
- Per-job/per-user configuration surfaces (API params, UI controls) for thresholds or `MaxParticipants` — env-var/deployment-level config only, per spec Non-scope.
